# Инструменты для спрайтов

Скрипты запускаются напрямую: `swift <файл> <аргументы>`.

## Правило про кадры

**Кадры не переписываются без разрешения владельца пака.** Каждая правка
растрового изображения необратима: и уменьшение масштаба, и пересчёт холста
с нецелым смещением дают пересэмплирование и теряют детали. Вернуть исходник
неоткуда, если он ещё не в git — а свежий импорт обычно ещё не в git.

Инструменты, которые пишут поверх кадров (`rescale-pack`, `seat-frames`),
сами кладут копию папки в `sprite-backups/<метка времени>/` перед первой
записью и прекращают работу, если копию сделать не удалось. Папка лежит вне
`Resources/`, иначе копии уезжали бы внутрь собранного приложения, и она
в `.gitignore`.

У обоих есть `--dry-run`: сначала показать числа, потом спрашивать.

## split-sheet.swift

Разбирает спрайт-лист на кадры и вписывает их в холст пака.

```bash
swift scripts/sprites/split-sheet.swift <лист.png> <куда> <действие> <ширина> <высота> <рост>
# пример: лист бега -> 19 кадров run_NN.png на холсте 102x104, рост 70
swift scripts/sprites/split-sheet.swift sheet.png /tmp/out run 102 104 70
```

Кадры вырезаются по связным областям, а не по равным долям ширины: доли
обычно не сходятся нацело, а соседние кадры на листе соприкасаются, и обрезка
прямоугольником захватила бы кусок соседа.

Линия земли берётся по самой нижней точке цикла, отступы от неё сохраняются —
покачивание не теряется. По горизонтали кадры центрируются.

Скрипт печатает число найденных кадров: если оно не совпало с ожидаемым,
лист не годится (кадры слиплись или в них есть оторванные детали).

## make-sheet.swift

Собирает отдельные кадры в один спрайт-лист — обратная операция к разбору.
Пригодится, чтобы отдать существующую анимацию как образец стиля.

```bash
swift scripts/sprites/make-sheet.swift <папка с кадрами> <лист.png> [--gap 10]
```

Кадры идут слева направо, в одном ряду, каждый в клетке общего размера и
выровнен по низу и центру — так же, как их ставит движок. Порядок берётся
по числу в конце имени, а не по алфавиту: иначе `_10` встало бы перед `_2`.

## reexport-action.swift

Пересобирает отдельные действия из исходных кадров сразу в масштаб пака.

```bash
swift scripts/sprites/reexport-action.swift <исходники> <пак> \
  "climb=0.4315,hang=0.4268,fall=0.4565,drag=0.4512" --dry-run
```

Кадры действий приходят из разных источников, и персонаж на них выходит
разного размера. Пересчитывать уже уменьшенные кадры пака значит
пересэмплировать их второй раз — вместо этого действие пересобирается из
исходника за один проход. Поэтому и подбирать коэффициент можно
итерациями: каждый прогон идёт от оригинала и потерю не накапливает.

Коэффициент считается по жёстким деталям. Высота для этого не годится: у
лезущей вверх собаки она законно больше, чем у стоящей. Площадь силуэта
тоже подводит — в разных позах лапы вытянуты по-разному. Работает площадь
ушей: они видны в любой позе и меняются только вместе с масштабом. Язык
для этого не подходит: в позах с открытой пастью его площадь резко растёт.

Инструмент отказывается работать, если содержимое не помещается на холст
пака, и делает резервную копию перед записью.

## downscale-pack.swift

Уменьшает пак в целое число раз и приводит кадры к общему холсту.

```bash
swift scripts/sprites/downscale-pack.swift Sources/eCorgiKit/Resources/Sprites 3 --dry-run
swift scripts/sprites/downscale-pack.swift Sources/eCorgiKit/Resources/Sprites 3
```

Уменьшение растра всегда теряет часть данных — этого не обойти. Потерю
здесь сводят к минимуму два решения:

- **Ланцош вместо обычной отрисовки.** На кадрах корги он даёт примерно на
  6% больше энергии градиента, чем усреднение 3×3, и вдвое меньше выбросов
  за пределы исходных значений, чем рисование Quartz с высоким качеством.
- **Перенос на общий холст целочисленным сдвигом.** Пересэмплирование
  происходит ровно один раз. Нецелое смещение при переносе — то, что
  размыло пак раньше: холст шириной 89 и кадр шириной 70 давали сдвиг
  на полпикселя, то есть ещё одно пересэмплирование поверх первого.

Отступ от земли и смещение от центра сохраняются, только делятся на тот же
множитель. Резервная копия делается обязательно.

## rescale-pack.swift

Меняет масштаб кадров по действиям и пересчитывает холст под новое
содержимое.

```bash
# выровнять масштаб между действиями и уменьшить пак
swift scripts/sprites/rescale-pack.swift Sources/eCorgiKit/Resources/Sprites \
  "idle=0.88,walk=0.967,run=1.007,jump=0.88,sleep=0.951" --dry-run
```

Коэффициенты задаются вручную, потому что подбирать их надо по данным.
Мерой масштаба не может служить высота: у бегущей собаки она законно меньше,
чем у стоящей. Работают две независимые меры — площадь силуэта и площадь
розовых деталей (уши, язык): это жёсткие детали, их размер меняется только
вместе с масштабом. Если обе меры дают близкий ответ, коэффициенту можно
верить.

Уменьшается кадр целиком, а не вырезанный персонаж: так сохраняются и отступ
от земли, и смещение относительно центра.

## order-frames.swift

Подбирает порядок кадров в цикле по похожести соседей: ищет кратчайший
замкнутый маршрут по кадрам (жадный обход плюс 2-opt) и печатает разрывы
между соседями.

```bash
swift scripts/sprites/order-frames.swift <папка> run [<куда писать>] [--start 3]
```

Инструмент вспомогательный, а не решающий: похожесть пикселей плохо отражает
соседство фаз в быстрых движениях, и порядок стоит проверять глазами по
контрольному листу. Куда полезнее его побочный вывод — расстояния между
кадрами: по ним сразу видно дубликаты (разрыв меньше 6) и провалы в цикле.

## seat-frames.swift

Сажает кадры на землю — убирает зазор между нижней точкой рисунка и нижней
кромкой холста. К этой кромке движок ставит лапы, поэтому зазор выглядит
как парение над полом.

```bash
# каждый кадр садится сам по себе (по умолчанию) — верно для шага:
# опорная лапа не должна отрываться от земли
swift scripts/sprites/seat-frames.swift Sources/eCorgiKit/Resources/Sprites walk --each

# весь цикл опускается на общую величину, превышения между кадрами сохраняются
swift scripts/sprites/seat-frames.swift Sources/eCorgiKit/Resources/Sprites run --cycle

# посмотреть, что будет, ничего не меняя
swift scripts/sprites/seat-frames.swift Sources/eCorgiKit/Resources/Sprites walk --each --dry-run
```

Сдвиг идёт целыми пикселями, без интерполяции — рисунок не мылится.

## contact-sheet.swift

Собирает все кадры действия в один лист с номерами и линией земли —
чтобы проверить разбор глазами.

```bash
swift scripts/sprites/contact-sheet.swift Sources/eCorgiKit/Resources/Sprites run /tmp/run.png
```

## place-cycle.swift

Переносит цикл анимации из полноразмерных кадров — например, из видео, где
персонаж идёт на месте, — на холст пака.

```bash
swift scripts/sprites/place-cycle.swift <кадры без фона> Sources/eCorgiKit/Resources/Sprites walk 0.124 --dry-run
```

Для всех кадров цикла преобразование одно: общая рамка содержимого, один
масштаб Ланцошем, один целочисленный сдвиг, земля — самая нижняя лапа за
цикл. Центрировать каждый кадр отдельно нельзя: тело дёргалось бы вбок,
когда вытягиваются лапы. Сажать каждый на землю тоже нельзя: пропало бы
покачивание. Старые кадры действия удаляются целиком, чтобы лишние с
большими номерами не остались в цикле.

При сильном уменьшении тонкий контур растворяется в заливке, и персонаж
выходит бледным и размытым: у ходьбы из видео доля тёмных пикселей контура
упала с 7.7% до 3%. Ключи `--outline 3 --sharpen 0.5` утолщают тёмные линии
до уменьшения и добавляют лёгкую резкость после — контур возвращается к
~10%, как у idle.

Как готовились кадры ходьбы из видео:

1. кадры извлекаются через `ffmpeg -vsync 0`;
2. период ищется по расхождению масок между кадрами `s` и `s+k`;
   полный шаг — 22 кадра при 24 кадрах в секунду (11 — это полшага:
   ближние и дальние лапы на стыке поменялись бы местами);
3. если в видео нарисована тень (как в беге), нейтрально-серые пиксели,
   связанные с краем, тоже уходят в фон — цветной контур корги заливку
   останавливает;
4. фон убирается заливкой от краёв по цвету фона, с мягкой альфой на
   кромке и вычитанием цвета фона из краевых пикселей, иначе на тёмном
   столе остаётся светлый ореол;
5. масштаб подбирается по росту и площади силуэта. Уши для этого не
   годятся, если рисунок другой: пропорции ушей у разных художников
   разные.

## inbetween.py

Дорисовывает промежуточные кадры, чтобы действие шло плавно при 12 кадрах
в секунду. Новые кадры такие же резкие и без новых цветов: каждый их
пиксель — пиксель соседнего исходного кадра, сдвинутый вдоль оптического
потока (выборка «ближайший сосед», без смешивания и двоения).

```bash
python3 -m venv /tmp/venv && /tmp/venv/bin/pip install opencv-contrib-python-headless numpy pillow
/tmp/venv/bin/python scripts/sprites/inbetween.py Sources/eCorgiKit/Resources/Sprites hop /tmp/hop --dry-run
/tmp/venv/bin/python scripts/sprites/inbetween.py Sources/eCorgiKit/Resources/Sprites hop /tmp/hop
# зацикленные действия — с --loop, тогда заполняется и стык последнего кадра с первым
```

Сколько кадров вставлять в промежуток, решает шаг между соседями — 90-й
перцентиль длины потока по силуэту. У ходьбы он ~1.8 px, у бега ~5.7 px;
по умолчанию `--target 5`. Исходные кадры копируются байт в байт, меняются
только номера. В пак скрипт не пишет: результат смотреть по контрольному
листу, переносить с резервной копией. Больше кадров — дольше действие:
длительность прыжка движок считает как `кадры / hopFPS`.

Ореол с альфой 1–6 вокруг силуэта (след Ланцоша) в разбрасывание не
идёт — иначе под лапами появлялись непрозрачные нитки.

Деталь, которая меняет форму (ухо из прижатого становится торчащим), пары
в другом кадре не имеет: сырой поток её рвёт, и вместо уха вырастает
«мех». Такие пятна находятся проверкой «туда и обратно», поток в них
заменяется плавным потоком окрестности, и деталь едет целиком: до
середины перехода — из левого кадра, после — из правого. Второй кадр
даёт только надёжные пиксели, чтобы не торчали обрывки старой формы.
Поток — DeepFlow из opencv-contrib: на поворотах он держит форму лучше DIS.

Второй признак беды — поток выворачивает участок (якобиан ≤ 0.2): так
большой поднятый хвост сжимается в маленький опущенный и в промежутке
рвётся в крючок с дырами, хотя проверку «туда и обратно» проходит. Такой
участок тоже едет целиком. Основной кадр выигрывает везде, куда долетел,
второй только заполняет открывшиеся места.

Чистка в конце убирает клочки, связанные с телом лишь по диагонали или
через почти прозрачный пиксель: связь ищется по плотным пикселям (альфа
≥ 128) сторонами. На кадрах пака она не снимает ни одного такого пикселя.

Последний шаг — ровный край. Выборка «ближайший сосед» сохраняет цвета,
но край силуэта выходит ступенчатым, а тёмная обводка рвётся. Силуэт
сглаживается на увеличенной вчетверо маске (размытие 0.8 px), кромка
получает альфу по доле покрытия, а цвет — обводки исходного кадра из
той точки, откуда пришёл пиксель. Внутренность силуэта не трогается.

## align-pack.py

Выравнивает действие по соседям, не пересэмплируя кадры: целочисленный сдвиг
по вертикали и приведение гаммы к образцу.

```bash
python3 scripts/sprites/align-pack.py <пак> --shift walk=1,run=1 --tone walk,run --like idle --dry-run
```

`--shift действие=N` поднимает кадры на N пикселей (отрицательное — опускает)
и отказывается работать, если при этом срезался бы рисунок. `--tone` подбирает
для каждого канала кривую «степень и усиление», совмещающую средние тона и
света действия с образцом из `--like`; чёрное не трогается, поэтому глаза, нос
и контур остаются как были. Кривая одна на всё действие — между кадрами
ничего не мерцает. Обе операции попиксельные, резкость не меняется.

`--out <папка>` пишет результат отдельно, для просмотра; без него скрипт
кладёт копию пака в `sprite-backups/` и пишет поверх. Нужны numpy и Pillow.

Так ходьба и бег, снятые с видео, приведены к тону остальных кадров: были
темнее и тусклее (средняя яркость 157 против 170, света 240 против 246).
