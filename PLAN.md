# eCorgi — план разработки desktop pet для macOS

> Мультяшный корги, живущий поверх рабочего стола, по мотивам классического eSheep 64.
> Стек: **Swift + AppKit/SwiftUI**. Поведение: **полный аналог eSheep**. Графика: **готовый спрайт-пак (внешний источник)**. Дистрибуция: **раздача .app друзьям/в интернет через Developer ID + нотаризацию**.

Составлено: 01.09.2026. На основе материалов в папке проекта: `eSheep-v1.1.dmg` (референс поведения), кадры бега кабана из Banana Kong (референс тайминга анимации), пробные ИИ-сгенерированные кадры корги.

---

## 1. Концепция

Маленькое фоновое приложение без окна с рамкой и без иконки в Dock (`LSUIElement`), которое рисует прозрачное окно с анимированным корги. Пёс живёт своей жизнью: ходит по нижнему краю экрана, забирается на верхние края открытых окон, свисает с их заголовков, засыпает, реагирует на курсор мыши, может быть подхвачен и перетащен пользователем. Иконка в строке меню (menu bar) даёт доступ к настройкам и управлению.

## 2. Технологический стек и архитектура

**Язык/фреймворки:** Swift 5.10+, AppKit (не SwiftUI для самого окна питомца — нужен точный контроль над `NSWindow`, прозрачностью и Z-order; SwiftUI допустим для окна настроек).

**Минимальная версия macOS:** рекомендуется таргет macOS 13 Ventura+ (баланс между охватом пользователей и современными API вроде `ScreenCaptureKit`/актуального `Accessibility` API). Если важна поддержка старых Mac — можно опустить до macOS 11.

**Ключевые системные API:**

| Задача | API |
|---|---|
| Окно питомца поверх всех окон, без рамки, кликабельное только по корги | `NSWindow` (`.borderless`, `NSWindow.Level.floating` или `.statusBar`), `isOpaque = false`, `backgroundColor = .clear`, `ignoresMouseEvents` переключается динамически |
| Отслеживание положения и границ других окон (чтобы «ходить» по их краям) | `CGWindowListCopyWindowInfo(.optionOnScreenOnly, kCGNullWindowID)` — даёт фреймы всех окон на экране без спец. прав |
| Позиция курсора в реальном времени | `NSEvent.mouseLocation` + глобальный монитор `NSEvent.addGlobalMonitorForEvents` |
| Перетаскивание корги мышью | Локальный `NSEvent` монитор на mouseDown/mouseDragged в окне питомца |
| Иконка и меню в строке меню | `NSStatusItem` (`NSStatusBar.system`) |
| Автозапуск при входе в систему | `SMAppService.mainApp.register()` (macOS 13+) |
| Игровой цикл / тики анимации | `CVDisplayLink` (плавнее) или `Timer`/`CADisplayLink`-аналог на 30–60 fps |

**Архитектура (модули):**

```
eCorgi/
├── App/
│   ├── AppDelegate.swift        — жизненный цикл, статус-бар меню, автозапуск
│   └── PetWindowController.swift — управление NSWindow питомца
├── Engine/
│   ├── GameLoop.swift           — тикер, обновление кадра
│   ├── ScreenEnvironment.swift  — сбор геометрии экрана и окон (полы, потолки, края)
│   ├── PhysicsHelper.swift      — гравитация, коллизии с краями, падение
│   └── CursorTracker.swift      — глобальный трекинг курсора
├── Behavior/
│   ├── BehaviorState.swift      — протокол состояния (enter/update/exit)
│   ├── StateMachine.swift       — переключение состояний + таблица весов/переходов
│   └── States/                  — Walk, Sit, Sleep, ClimbWindowEdge, HangFromTitleBar,
│                                    Fall, Drag, RunFromCursor, JumpBetweenWindows, Scratch, Bark...
├── Rendering/
│   ├── SpriteAnimator.swift     — покадровая анимация из спрайт-листа/PNG-последовательности
│   └── SpriteAtlas.swift        — загрузка и кэш кадров
├── Settings/
│   ├── PreferencesWindow.swift  — SwiftUI-окно настроек (скорость, звук, размер, автозапуск)
│   └── SettingsStore.swift      — UserDefaults-обёртка
├── Resources/
│   └── Sprites/                 — спрайт-пак (см. раздел 3)
└── eCorgiTests/                 — unit-тесты для StateMachine и ScreenEnvironment
```

Центральная идея: **конечный автомат состояний** (state machine), где каждое поведение — отдельный класс/структура с `enter()`, `update(dt)`, `exit()`, и таблицей вероятностных/событийных переходов (как в оригинальном Sheep/Shimeji — у поведений есть вес выбора и условия применимости, например «лазать по краю» доступно только если рядом есть подходящее окно).

## 3. Спецификация спрайтов и анимаций

Раз графика будет приходить готовым спрайт-паком — вот техзадание, которое стоит передать художнику/источнику ассетов, чтобы он влился в движок без переделок.

**Формат:** PNG с альфа-каналом (прозрачный фон), либо один spritesheet на каждое действие, либо последовательность пронумерованных файлов (`walk_00.png`, `walk_01.png`, …) — по образцу уже собранных в проекте кадров кабана.

**Разрешение кадра:** рекомендовано 128×128 px (можно 2x retina-вариант 256×256) с запасом полей вокруг персонажа, чтобы лапы/уши не обрезались при повороте.

**Ориентация:** только «вправо» — отражение по горизонтали (`CGAffineTransform(scaleX: -1, y: 1)`) для движения влево, отдельные кадры «влево» не нужны.

**Минимальный набор анимаций (для полного аналога eSheep):**

| Состояние | Кадров (ориентир) | Комментарий |
|---|---|---|
| Idle / Sit (сидит) | 2–4 | лёгкое дыхание/моргание |
| Walk (ходьба) | 6–8 | по образцу уже готового бега кабана |
| Run (бег, реакция на курсор) | 6–8 | быстрее и с наклоном корпуса |
| Sleep (сон) | 2–4 | + отдельный редкий кадр «Zzz» |
| Sit-down / Stand-up (переход) | 2–3 каждый | сглаживает Walk↔Sit |
| ClimbUp / ClimbSide (лазание по краю окна) | 4–6 | цепляется лапами за верхний край окна |
| HangFromEdge (свисает с потолка/заголовка окна) | 2–4 + анимация покачивания | |
| Fall (падение) | 2–3 | + приземление (Land, 2 кадра) с «пыльным» эффектом (опционально) |
| Drag / Held (питомца тащит мышь пользователя) | 2–3 | лапы дёргаются в воздухе |
| Scratch / Dig (чешется, роет) | 4–6 | случайное «характерное» поведение |
| Bark / React (реакция на клик/событие) | 3–4 | опционально, если решите добавить звук |
| Jump (прыжок между окнами) | 3–5 | подготовка-полёт-приземление |

Итого ориентировочно **45–70 уникальных кадров** для полного набора — это сопоставимо по объёму с уже отрисованными 24 кадрами бега кабана, так что оценка реалистична.

**Именование файлов:** `<action>_<frame>.png`, например `walk_00.png … walk_07.png`. Такое соглашение проще всего мапится на `Behavior/States/*` один-в-один.

**Что нужно зафиксировать в брифе художнику:** стиль уже задан двумя пробными ИИ-кадрами (мультяшный, толстый чёрный контур, крупные глаза) — приложить их как референс стиля вместе с этой таблицей.

## 4. Система поведений (state machine, аналог eSheep)

Логика близка к оригинальному Sheep/eSheep и его идейным потомкам (Shimeji и т.п.):

1. **Ground states** — Idle, Sit, Sleep, Walk, Scratch: питомец ходит по нижнему краю **основного экрана** (`NSScreen.main.visibleFrame`), периодически останавливается, садится, изредка засыпает после долгого бездействия.
2. **Window awareness** — раз в тик (не каждый кадр, для экономии CPU — например 4–5 раз/сек) опрашивается `CGWindowListCopyWindowInfo`, строится список «полок» — верхних и боковых границ видимых окон, по которым питомец может перемещаться. Если корги оказывается рядом с подходящим краем — с некоторой вероятностью запускается `ClimbWindowEdge`.
3. **Climb & Hang** — после залезания на верх окна питомец может пройтись по этому краю (как по земле, но выше), с шансом перейти в `HangFromTitleBar` (цепляется и свисает, покачиваясь) или спрыгнуть/упасть вниз — переход в `Fall`.
4. **Fall / Gravity** — простая физика: если под питомцем нет опоры (ни земли, ни края окна), включается гравитация до столкновения со следующей опорой или с нижним краем экрана.
5. **Cursor reaction** — если курсор мыши оказывается близко к питомцу (радиус настраивается), с вероятностью включается `RunFromCursor` (убегает) — фирменная фишка оригинального eSheep.
6. **Drag interaction** — `mouseDown` на спрайте питомца замораживает state machine и переходит в `Drag`: питомец следует за курсором с задержкой (пружинный лаг для естественности), лапы «болтаются». `mouseUp` — переход в `Fall`, если в воздухе, иначе `Land`.
7. **Multi-window jump** — иногда, оказавшись у края одного окна рядом с другим окном на похожей высоте, питомец может «перепрыгнуть» между ними.
8. **Переходы** — управляются таблицей весов (вероятность выбора следующего состояния) + модификаторами по контексту (например, вес `Sleep` растёт со временем бездействия; `ClimbWindowEdge` доступен только если рядом реально есть край).

**Практический подход к реализации:** взять `BehaviorState`-протокол, каждое состояние — отдельный `.swift`-файл, а таблицу переходов вынести в один JSON/Plist-файл (`behaviors.json`) с полями `{state, animation, minDuration, maxDuration, nextStates: [{state, weight, condition}]}`. Это позволяет донастраивать «характер» корги (например, сделать его более сонным или более игривым) без пересборки — полезно и для будущих вариаций/скинов.

## 5. Взаимодействие с системой и UX

- **Строка меню (`NSStatusItem`)**: иконка-мордочка корги, меню с пунктами «Разбудить/Уложить спать», «Настройки…», «О программе», «Выход», а также опционально «Позвать корги» (телепорт к курсору) и «Добавить ещё одного корги» — если решите поддержать несколько питомцев одновременно.
- **Окно настроек** (SwiftUI): скорость движения, размер спрайта (Slider 0.5x–2x), включить/выключить звук, автозапуск при входе (`SMAppService`), количество питомцев, «выбор скина» (задел на будущее, если появятся другие породы/раскраски).
- **Права доступа:** `CGWindowListCopyWindowInfo` не требует Accessibility-разрешений для базового чтения фреймов окон. Если в будущем понадобится более тонкое отслеживание (например, активное окно, за которое реально «цепляется» питомец, включая его точный заголовок) — может понадобиться Screen Recording permission (macOS требует его для части `CGWindowList` данных начиная с Catalina/Sonoma-ограничений) — стоит заложить обработку экрана запроса разрешения и понятный onboarding-экран при первом запуске.
- **Множественные мониторы:** учесть `NSScreen.screens`, дать питомцу «путешествовать» между экранами по их видимым границам.
- **Производительность:** ограничить частоту опроса окон (не каждый кадр), использовать `CVDisplayLink` с троттлингом до ~30fps для анимации (для питомца этого более чем достаточно и экономит батарею на ноутбуке).

## 6. Сборка, тестирование, CI

- **Xcode-проект** (`.xcodeproj` или SPM-based) с таргетом macOS App.
- **Unit-тесты**: `StateMachine` (переходы по весам, граничные условия), `ScreenEnvironment` (парсинг геометрии окон на моках), `SpriteAnimator` (корректность цикла кадров).
- **Ручное QA-тестирование:** отдельный чек-лист — поведение на 1 и 2+ мониторах, поведение при закрытии/сворачивании окон под питомцем, поведение при Mission Control/Spaces, потребление CPU в Activity Monitor (цель: <1–2% в простое на Apple Silicon).
- **CI (опционально):** GitHub Actions с `xcodebuild test` на macOS runner при каждом пуше.

## 7. Подпись, нотаризация и дистрибуция

Так как приложение будет раздаваться друзьям/в интернет (не только «для себя»), Gatekeeper обязательно потребует подпись и нотаризацию — иначе пользователи увидят предупреждение «файл повреждён» или «не удалось проверить наличие вредоносного ПО».

1. **Apple Developer Program** — учётная запись разработчика ($99/год), нужна для получения **Developer ID Application** сертификата.
2. **Code signing** — подписать `.app` сертификатом Developer ID (`codesign --deep --sign "Developer ID Application: ..."`).
3. **Notarization** — отправить собранный `.app`/`.dmg` через `xcrun notarytool submit ... --wait`, дождаться `Accepted`, затем **staple** тикет (`xcrun stapler staple`).
4. **Упаковка в DMG** — красивый инсталлятор через `create-dmg` или встроенный Disk Utility-скрипт, с фоном/иконкой и алиасом на `/Applications`.
5. **Автообновления** — рекомендуется встроить **Sparkle** framework, чтобы будущие версии (новые скины, баг-фиксы) доставлялись пользователям автоматически, без ручной переустановки.
6. **Опционально — сайт-визитка/страница релиза** — GitHub Releases или лендинг с описанием и .dmg для скачивания.

*Если позже возникнет желание выложить в Mac App Store — потребуется дополнительно: App Sandbox (сильно ограничит доступ к `CGWindowListCopyWindowInfo` и глобальному mouse-трекингу, придётся переработать часть Engine), прохождение App Review, другой процесс подписи (App Store Connect). Это стоит держать в уме как отдельную, более сложную ветку релиза, а не смешивать с прямой раздачей.*

## 9. Риски и технические сложности

- **Определение краёв чужих окон** — самая нетривиальная часть; `CGWindowListCopyWindowInfo` даёт фреймы, но не всегда надёжно отличает реальные окна приложений от системных/декоративных слоёв — потребуется фильтрация по `kCGWindowLayer`/`kCGWindowOwnerName`.
- **Права на запись/чтение экрана** — Apple периодически ужесточает требования (Screen Recording permission) для части оконных API; стоит закладывать fallback-режим «только нижний край экрана» без осведомлённости об окнах, если пользователь не дал разрешение.
- **Производительность на батарее** — глобальный мониторинг мыши и опрос окон должны быть максимально дешёвыми; профилировать через Instruments (Time Profiler, Energy Log).
- **Gatekeeper/нотаризация** — процесс может занять время на первую настройку сертификатов; закладывать это в план заранее, а не в последний момент перед релизом.
- **Согласованность анимаций спрайт-пака** — если пак придёт от внешнего источника не по ТЗ из раздела 3, часть таймингов/переходов в `Behavior/States` придётся подстраивать вручную под реальное количество кадров.
